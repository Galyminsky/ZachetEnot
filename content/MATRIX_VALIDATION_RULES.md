# Правила проверки матрицы навыков A–H

Эти правила задают критерии проверки существующей матрицы при получении исходников. Они не добавляют навыки, не устанавливают новый перечень A–H и не изменяют исходные статусы. Применять вместе с материалами аудита 2.0; новый полный аудит учебников не проводить.

## Обязательные поля каждой записи

| Поле | Правило |
|---|---|
| `skill_id` | Обязательный, непустой, уникальный и стабильный идентификатор. Сохранять принятый исходный ID; не генерировать замену при переименовании формулировки. Любой предлагаемый ID для строки без ID отдельно согласовать и документировать. |
| `section` | Одно значение из A, B, C, D, E, F, G, H. Исходное распределение сохранять; перенос раздела — только по подтверждённому решению с записью причины. |
| Формулировка навыка | Описывает проверяемое действие/знание конкретно и однозначно. Не подменять навык широкой темой или видом вопроса. При редактуре сохранить исходный текст и основание изменения в истории/примечании. |
| Тема учебной программы | Ссылка на существующую тему программы с принятым названием/ID. Не придумывать новую тему для заполнения пустоты; не смешивать тему программы и формулировку навыка. |
| Источник | Указание на подтверждающий источник с достаточной точностью для повторной проверки: документ/издание/версия и страница, раздел/пункт либо точная ссылка/идентификатор предоставленного материала. |
| Подтверждение | Фиксирует, что именно подтверждает источник и/или вывод аудита 2.0, и к какой строке/ID относится. Наличие названия источника без привязки к навыку недостаточно. |
| Статус проверки | Сохранить исходный статус и его смысл. Проверить, что статус подтверждён исходным аудитом/решением. Не менять статус без документального основания; новые статусы/легенду не вводить, пока не получено правило источника или решение владельца. |
| Связь с будущими вопросами | Поле/связь допускает ноль или более стабильных ID вопросов и позволяет связать вопрос с навыком. До появления мастер-банка оставить связь пустой/ожидающей, а не создавать фиктивные ID или контент. |

## Проверки целостности и дублирования

1. `skill_id` уникален во всей матрице A–H, а не только внутри листа или раздела.
2. Повторный запуск проверки на том же входном файле даёт тот же набор ID; идентификатор не зависит от номера строки, сортировки или текущей формулировки.
3. Каждая строка отнесена ровно к одному разделу A–H, если исходная спецификация не предусматривает явную множественную связь. Любую неоднозначность отметить, не разрешать по догадке.
4. Каждая формулировка описывает проверяемый навык и связана с темой программы и подтверждением; отсутствующие данные получают статус замечания/блокера, а не заполняются выдуманным содержимым.
5. Поиск дублей выполнять как минимум по точному совпадению нормализованной формулировки и по смысловому совпадению внутри/между разделами. Совпадение темы само по себе не доказывает дубль. Возможное объединение двух навыков не выполнять автоматически: сохранить обе исходные строки и запросить решение с указанием ID.
6. Связи будущих вопросов сверять по существующим ID банка, когда банк появится. Удалённый/неизвестный ID отмечать ошибкой ссылки; не создавать вопросы в ходе проверки матрицы.
7. Изменения формулировок, раздела, темы, источника, статуса или ID должны быть прослеживаемы к исходной строке и иметь основание/ссылку на принятое решение.

## Результат проверки

Для каждой записи фиксируются результат и доказательство проверки обязательных полей, стабильности ID, раздела A–H, темы/источника, статуса, связей вопросов и дублей. Отдельно фиксируются ошибки, предупреждения и открытые вопросы. Нельзя объявлять матрицу принятой при потерянных строках/ID, необъяснённых изменениях статусов или неразрешённых критических дублях.

Поскольку исходная матрица и аудит 2.0 сейчас отсутствуют в проекте, эти правила пока не применялись к строкам навыков; статусы навыков не проверялись и не менялись.
