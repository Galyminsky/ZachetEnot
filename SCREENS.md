## Статус вёрстки UX/UI
По подтверждению владельца от 2026-11-03 все 22 экрана и состояния реализованы, визуально проверены владельцем; этап вёрстки закрыт. Ранее зафиксированные ниже ограничения функциональности сохраняются и не считаются устранёнными этой приёмкой. Исторические замечания о непроверенном рендере относятся к предыдущим проходам агента.

## Маршрут
Выбор класса (1 из 2) → Выбор предмета (2 из 2, кнопка «Назад») → Темы (главный экран, нижняя навигация «Темы / Прогресс / Настройки», кнопка настроек вверху справа).

Основная кнопка «Продолжить» (AppButton Primary, стрелка) 56 dp, под ней подпись 12/15 TextSecondary по центру. Заголовки 32/36 (headlineLarge) и 28/34 (headlineMedium): в экранах letterSpacing -1 и -0.8, в ките -0.7, принято значение кита (расхождение 0.3 px).

## Принятые решения
- Экраны 1–2 показываются только при первом запуске, далее сразу открываются «Темы»; смена класса и предмета доступна через настройки.
- Нижняя навигация в MVP не используется (вкладка «Прогресс» отсутствует); настройки открываются кнопкой в шапке.
- Пройденная тема открывается повторно, со стрелкой (отличие от макета).
- Тексты карточки прогресса и подписей для состояний, которых нет в макете, пишет Claude и согласует владелец.
- Экраны не применяют системные insets, их задаёт хост (Activity или NavHost).
- UI-модели экранов (`TestScreenState`, `PrepUiState`) содержат готовые строки; сборка из доменной модели выполняется в 2B.
- Контент прокручивается, нижний блок с кнопкой закреплён.
- Экраны результата и разбора ошибок принимают готовые строки (`ResultUiState`, `ReviewUiState`).
- При нескольких ошибках карточки идут подряд с отступом 16 dp; в макете показан только случай одной ошибки.
- Подпись «Ошибка/Ошибки» и тексты результата формирует хост; склонение и тексты из домена собираются в адаптации.

## Variant 2: расхождения с действующей логикой (узлы 64:428–64:675, 75:501–75:611, 76:428–76:519)
- Варианты теста с вводом текста, сопоставлением и последовательностью (76:428, 76:467, 76:519) пока не запускаются: действующая модель Question и TestSession принимают только идентификатор выбранного варианта.
- Разбор конкретных ответов после попытки (64:627, 75:517) пока недоступен: TestSession сохраняет только правильность, TestResult — итог и число ошибок по правилам, без выбранных ответов. Кнопка разбора скрыта для реального результата.
- Переключатель звука (64:675) показан без действия: нет управления звуком и сохранения настройки; в подключённом экране он отключён.
- История попыток и длительность результата не сохраняются: время текущей попытки вычисляется локально при показе результата. Историю прогресса из макета нельзя наполнить из существующего ProgressRepository.
- Выбор класса и предмета не сохраняется между запусками; в текущем каталоге доступен только 3 класс и русский язык. Состояния других классов и предметов остаются демонстрационными.
- Состояние «Нет контента» (75:611) не связано с отдельным контрактом загрузки/ошибки; пустой или отсутствующий учебный банк нельзя подменять вымышленными темами и вопросами.

## Шаг 3 — 12 дополнительных состояний по локальным PNG
- `design-reference/ZE · S1–S12` однозначно сопоставлены с двенадцатью состояниями по номерам и названиям файлов.
- S1–S3: в существующем `TestScreen` оформлены ввод текста, сопоставление и последовательность; Preview используют данные соответствующих PNG. Рабочий маршрут `MainActivity` по-прежнему подаёт только `AnswerUi.Choice`: действующие `Question` и `TestSession` принимают ответ по id варианта. Проверка и сохранение ответов для остальных форматов не поддержаны; демонстрационные Preview не считаются бизнес-логикой.
- S4: неуспешный результат оформлен в существующем `ResultScreen` и подключён к фактическому результату попытки. Кнопка разбора доступна только при наличии полного списка ошибок текущей попытки.
- S5: состояние без ошибок оформлено в существующем `ReviewScreen` и доступно после попытки без ошибок.
- S6–S10: стандартные AlertDialog заменены общим `StateDialog` в сценариях выхода, предупреждений таймера, истечения времени и сброса прогресса. Дедлайн и пороги предупреждений не изменены.
- S11: состояние недоступной функции открывается из карточки будущих предметов. Переключение звука по-прежнему не поддержано.
- S12: состояние отсутствия учебного контента открывается, когда для выбранной темы недостаточно вопросов для теста; загрузка контента как отдельный сценарий ошибки не моделировалась.
- Ограничение разбора: приложение хранит ошибки только в памяти текущей попытки. Если попытка завершилась по таймеру с неотвеченными вопросами или правило не найдено, подробных данных для показа каждой ошибки нет; отсутствующие ответы и объяснения не имитируются. История попыток и доменный контракт в этом шаге не менялись.
- После проверки ссылок существующие компоненты и drawable не удалялись: часть используется Preview, часть — экранами и навигацией; доказанно лишних среди затронутых файлов не найдено.
